# Courses, photos and accepted-friends posts

Courses is a primary tab on desktop and mobile. It offers worldwide course search, the user's real played-course collection, previous-round history and a direct route to Passport. Mobile keeps five controls: Home, Rounds, Add, Courses, Profile; Passport is inside Courses and Friends inside Profile. Desktop exposes all six pages with Add beside search.

Round entry accepts up to three JPG, PNG or WebP files, each under 15 MB before processing. Images are decoded and redrawn into bounded JPEGs, at most 90,000 data-URL characters each. This strips original metadata; full-resolution originals are not retained. Photos can be removed before saving, retained in drafts, reopened with a round, and included in V7 exports/imports. Old V7 records without photos remain valid.

This initial implementation stores compressed photos inside the existing private journal JSON in Supabase and the account-local cache, rather than a public bucket. A 3.5-million-character journal preflight and actual storage-failure handling protect the browser cache; saving stops with a message if space is unavailable. This is a bounded journal, not unlimited photo storage. A future larger photo library should move media to private object storage with the same audience rules.

Posting is explicit and off by default. Checking “Post this round to accepted friends” changes the submit label to “Save & post”. The private round saves first. If posting fails it remains private, with an error and retry instructions. A post contains the profile display name, course, date, holes, strokes, tees, notes and attached photos. Private journal edits do not alter an existing snapshot until reposted. A post can be removed in Friends without deleting the private round. Deleting an authenticated round removes its post first; the app requires a connection for that removal.

Friends is now intentionally backed by Supabase, replacing the fictional demo page. Users exchange account friend codes, send a pending request and accept it from the recipient account. No invitation email or external message is sent. There is no public user directory or anonymous feed. Both participants may remove a connection; neither can change its participant IDs. The recipient alone can transition pending to accepted. Accepted friends can see all currently posted snapshots from each other. Removal blocks future reads; already viewed or downloaded images cannot be recalled.

`dogleg_connections` and `dogleg_round_posts` have RLS enabled, explicit authenticated grants and no anonymous table access. Post reads require ownership or an accepted connection. Insert/update/delete require ownership. The server validates bounded payloads and rejects external image URLs, SVGs and oversized photo arrays. No service-role key is shipped.

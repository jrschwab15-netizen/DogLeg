# Course data import

OpenGolfAPI is integrated into round logging and the course-search dialog. Users choose a course, then a named tee/rating set. Available course rating, slope, total yardage/par and per-hole yards, par and handicap (stroke index) are filled from the selected card. Men's and women's rating sets remain distinct. Unknown values are blank/dashes. The current score, date, notes and photos are preserved during lookup and tee changes. Imported hole metadata appears below optional hole-score inputs and in an expandable scorecard.

Initial Supabase import: 10 real course cards, 84 tee sets, from public OpenGolfAPI responses. These are an initial cache, not a claim that every course has been imported. The search continues to access the provider's larger directory. Further selected courses are imported on demand for signed-in players through the authenticated `course-data` Edge Function. Guests can read the shared cache and retrieve public provider cards directly without uploading a journal. Photon remains the worldwide/name-only/nearby fallback; those listings do not imply tee-card availability.

`dogleg_course_catalog` contains public course facts only. RLS and explicit grants allow anonymous/authenticated SELECT and deny INSERT/UPDATE/DELETE. The Edge Function validates the user's session, rejects anonymous auth users, restricts browser origins, accepts only bounded GET search/UUID detail requests, and fetches a fixed upstream host. Only that server code uses the service-role environment variable; it does not accept caller-supplied course JSON. No service-role key is shipped to the browser or GitHub. No existing journal/post policies changed.

Local cache: up to 20 course cards, retained for offline repeat use. Shared and local card freshness is 30 days, with stale cached cards usable if refresh fails. Account journals store the selected tee snapshot and attribution, not the entire course directory. Existing V7 backups remain valid; imported snapshots are validated on import. Editing a saved round restores the selected tee/card. Manual corrections remain possible. No rounds are posted automatically.

When 9 holes are played from an 18-hole card, select front/back nine. The 18-hole rating and slope are cleared; enter the actual nine-hole figures. The UI explicitly labels the full 18-hole tee totals. Ratings are never halved or invented. Missing source yardages are never filled from another tee. This does not create an official WHS Handicap Index.

Attribution: © OpenStreetMap contributors (ODbL 1.0) via OpenGolfAPI. Visible attribution links to https://opengolfapi.org/attribution/ and snapshots carry attribution/license fields. Data license: ODbL 1.0; keep applicable attribution/share-alike obligations when publishing a derived database. API docs: https://opengolfapi.org/docs/ . No paid provider subscription was purchased.

Implementation: src/course-schema.js (shared normalization/validation), src/course-data.js (form/cache integration), supabase/functions/course-data/index.ts (authenticated importer), migration 202610200004 and supabase/tests/course_catalog.sql. Build copies the shared schema into the Edge Function directory. scripts/import-course-seeds.cjs downloads the initial public cards into ignored dist/ for an explicit administrative import; it does not publish or overwrite user data.

Verification: feature/cloud/social/journey/course-data/importer tests pass. Database rollback tests confirm anon and authenticated read access and denied writes. Live anonymous importer call returns 401. Local browser guest flow verified Supabase catalog search, Pebble Beach White/Male selection (71.7/135), 18 hole rows, save/reopen restoration, and nine-hole rating clearing. Mobile dialog fits at 390px without horizontal overflow. A guest-only QA round was saved locally, without posting. The signed-in importer path is covered by authenticated handler tests; a real signed-in session was not used for an end-to-end import in this run.

Approval review rejected the first unauthenticated importer proposal. The deployed replacement requires a verified user session and leaves the gateway JWT check enabled.
# Automatic rating and slope

Selecting a directory course now loads and applies a tee card without requiring an extra dropdown selection. The form visibly identifies the chosen tee and rating gender. Priority is the previous exact provider tee ID, a unique previous tee name, a complete White tee card, then the first complete published card (or the first card if none is complete). This is a starting selection, not a recommendation of appropriate tees or rating gender; players must check the displayed set. Changing the tee dropdown updates rating/slope and hole facts together. Typing a recognized unambiguous tee name also fills its card; ambiguous names require the dropdown.

New forms start rating/slope empty instead of using 72/113. Switching course names clears stale numbers. Async loading does not overwrite manual rating/slope entered while waiting, a different course, a closed form or a different account. Existing saved snapshots remain intact. Missing values stay blank; a nine selected from an 18-hole card still requires the published nine-hole rating/slope, with no halving or invented slope.

Verified with the full test suite and local browser selection of Pinehurst No. 2: automatic fill, White tee change to 70.7/126, and both values cleared for nine holes. No rounds were saved during that check.
